# 小红书家庭网络出口

2026-10-10 实测：相同账号从云服务器发送的私信，在发送端有成功回执和历史记录，接收手机不可见；官方网页通过家庭出口发送测试 D 后，账号所有者确认接收手机可见。云端登录也出现过平台 300012 /「IP存在风险」。这些证据支持固定家庭出口，尚不能证明平台具体按国家或 IP 类型拦截。

## 运行方式

工作台、数据库和模型调度继续运行在服务器。`xhs-home-tunnel.service` 通过 Tailscale 和 SSH 在服务器的 `127.0.0.1:18890` 提供 SOCKS5，Mac mini 只提供出站连接，不保存工作台 Cookie。隧道仅监听本机，不修改服务器的默认路由、Tailscale exit node 或其他服务出口。

`xhs_network.mode: home` 时，PC/Creator 登录、账号校验、笔记读取、创作者发布与上传、私信认证/历史及 WebSocket 使用显式代理，DNS 也从家庭端解析。SDK 的其他平台和模型服务仍按各自现有配置访问。不能只给 HTTP 设置代理而让 WebSocket 直连。

2026-10-10 Creator 登录排查：此前 Creator 适配器未传入家庭代理，二维码和短信初始化仍走服务器直连。现已统一出口并关闭每次登录调用的 HTTP 客户端。真实匿名探测中，两种出口都曾收到 CAS 二维码 HTTP 406；家庭出口的官方网页登录页面能正常加载，但未发送真实短信，不能宣称验证码发送已经恢复。遇到平台拒绝或安全验证时，先在官方创作服务平台登录，再在账号矩阵使用 Creator Cookie 导入。界面显示可操作的中文错误，切换登录方式取消旧请求，避免旧二维码错误干扰短信登录。

配置示例见 `runtime.example.yaml`。服务器配置文件和 SSH 私钥不得提交 Git。`home` 缺少有效代理地址时拒绝连接；代理断开或失效时不会降级直连。`direct` 只保留兼容其他部署，当前线上必须设为 `home`。

## 安装

服务器安装 `requirements.txt`，将 `xhs-home-tunnel.service` 安装到 `/etc/systemd/system/` 并启用。单元内的用户、Tailscale 地址、密钥和本地端口应与部署环境一致。SSH 主机密钥须预先验证并登记，单元使用 `StrictHostKeyChecking=yes`。Mac mini 的 `authorized_keys` 条目限制来源为服务器的 Tailscale IP，使用 `restrict,port-forwarding,command="/usr/bin/false"`，只开放隧道，不允许远程 shell。

```bash
sudo install -m 644 deploy/xhs-home-tunnel.service /etc/systemd/system/xhs-home-tunnel.service
sudo systemctl daemon-reload
sudo systemctl enable --now xhs-home-tunnel.service
sudo systemctl restart xhs-web.service
```

首次接入沿用 24 小时临时授权。Mac mini 上确认长期使用后，仅移除该公钥条目的 `expiry-time`；随后清空配置 `xhs_network.authorization_expires_at` 并重启工作台，页面才取消到期提示。在实际更新远端授权前，不应隐藏提示。SSH 到期限制新登录，已有隧道可能仍存活，因此不能仅凭当前在线认为长期授权已完成。

## 连接检测和断线行为

2026-10-10 账号会话排查：10:26 扫码的 PC 账号在 18:23 显示失效；随后从家庭出口分别使用登录客户端与业务客户端读取 `/api/sns/web/v2/user/me`，两次均 HTTP 200、业务码 -100。同出口的 leo 账号均成功（code 0、guest false）。失效 PC 账号此前仅保存过一次 Cookie。旧版检查丢弃业务码并把所有异常标记 expired，IM 虽在内存合并部分响应 Cookie，却没有写回数据库。证据能确认该会话已失效和持久化缺口，不能证明具体撤销原因；Creator 的上次成功状态也不能证明 PC 会话有效。

监听现在复用同一个 Auth，每 10 分钟调用 user/me 复核身份；成功的 user/me 和 IM HTTP 响应合并平台轮换 Cookie，连接成功、复核成功及每 25 秒将当前 Cookie 加密写回现有版本。版本仍代表扫码/导入，不因周期保存无限增长。条件更新防止旧连接覆盖新扫码或其他检查保存的凭证。明确 -100 标记失效并等待新 Cookie，更新后自动重连；300012 标记需验证，其他检查失败标记待检查，不暴露原始异常。失败响应下发的匿名 Cookie 不作为续期保存。没有开启监听的账号仍通过手动检查刷新；本次没有增加新的后台账号流量。

此机制只接收平台实际下发的凭证更新，并不保证登录永久有效，也不能把已被撤销的 Cookie 恢复成登录态。失效账号需要重新扫码绑定 PC；同一 external_user_id/sub_type 会更新原账号。设备状态仍主要在当前 Auth 内存中，服务重启后的完整浏览器设备状态恢复不是本次实现范围。

后端每 15 秒通过同一 SOCKS 出口向小红书做一次无 Cookie 的 HTTPS HEAD 检测（8 秒超时、保持 TLS 校验）。只有平台正常响应才标记在线；平台限制响应单独显示。健康状态超过 45 秒未更新会暂停处理。页面「检测连接」只检测网络，不发私信。健康检测证明网络可达，不代表账号仍登录，也不证明某条私信送达。

私信 worker 在建立连接、处理队列和声明发送前检查健康状态。断线时显示「家庭网络断开 · 已暂停」，连接恢复后自动重连。每次发送记录当时的出口名称、IP 和检测时间，不保存代理凭据。隧道在离线期间不能绕过代理访问云端。

私信页后台刷新与图片加载失败不弹全局错误；失败图片显示单独的重试按钮，后台刷新只显示一条页面内提示。监听、网络、消息记录分别保留成功结果，失败项明确标注为上次结果；恢复后清除刷新提示。轮询等待本次请求完成后再延迟 5 秒，后台读取超时为 15 秒；切换账号或离开时取消在途请求。网络恢复但监听仍暂停时，显示「家庭网络已恢复 · 等待监听重连」，不把出口可达当成监听已连接。

2026-10-10 页面回归：模拟 12 张图片全部加载失败、消息轮询 503、恢复 200，确认零全局错误弹窗、监听状态仍能更新、只显示一条刷新提示并在恢复后清除。生产 HTTPS 页面连续观察 30 次 API 响应均成功，无 JS 异常；未复现截图发生时的具体请求失败原因，未发送测试私信。

在途发送缺少匹配成功回执，继续进入 `uncertain` 并阻塞同一会话，不能因网络恢复自动重发。暂停的会话及原因会固定显示在监听页顶部，可以核对接收端或跳过旧回复恢复。

每次重连先分页读取平台单人会话列表，再补收最近两天内、启用监听以后且晚于该会话最后已接收消息的文字。已接收的稳定消息 ID 去重，自己的消息、撤回和非文字内容不触发回复。补收完成后再启动实时读取和模型调度，让连续消息按时间顺序入队并由最新消息合并判断。会话列表和历史各自限定最多 30 页；无法完整读取时暂停并重试，不把不完整历史当作成功。该机制覆盖正常断线和服务切换期间的新会话消息，不追补超过两天的中断。

重新回复前仍同步两天历史，并按既有规则合并新消息、重新判断过期草稿。手机未收到的旧回复保留审计记录，不批量补发或改成已送达。
