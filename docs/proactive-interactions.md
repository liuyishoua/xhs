# 主动互动

入口：`/platforms/xhs/proactive`，侧栏「主动互动」。

每个 PC 账号有三张独立配置卡，可以同时开启：

- 互动回访：开关、间隔分钟、每轮最多回访人数。读取评论和点赞通知各第一页，
  合并用户、跳过近期已联系者。每人只取最新一篇作品，读不到就跳过，不回退到旧作品。
- 主动评论探索：搜索主题、每轮最多搜索 X 篇、每篇最多发送 Y 条评论、开关、间隔和互动偏好。
  搜索主题不为空时读取搜索第一页，对每篇符合条件的笔记分别生成最多 Y 条不同评论，
  本轮最多 X × Y 条。主题留空则保持原推荐流及原每轮评论总上限，不改变已有定时策略。
- 主动私信探索：搜索主题必填、每轮最多搜索笔记数、最多私信作者数、开关、间隔和互动偏好。
  每位作者每轮只联系一次，文字私信基于搜索命中笔记的正文生成。
  「同时分享命中的笔记」开启时先发送命中笔记的链接，成功回执后再发一条文字；
  关闭时只发送文字。分享使用现有文字消息通道，不是原生笔记卡片。

间隔 1–10080 分钟，回访、每帖评论、私信人数上限分别为 1–10，探索浏览上限 1–20。
新配置默认搜索 3 篇、每篇最多 1 条评论；已保存的搜索数量保持原值。
三个策略均保留「互动偏好（选填）」并分别支持每天开始和结束时间（北京时间）。
默认 00:00–23:59 全天；结束早于开始时跨午夜。结束时间包含该分钟。
定时队列和「立即运行」都遵循时段；时段外手动运行返回说明。
已排队但未开始的任务等待下一次开放；生成评论跨过结束时间时不再发送新评论。
私信每条发送前检查时段，尚未发送的消息等待下一次开放，不重复已提交的笔记链接。
上限不是必须完成的数量；无合适内容可以不发。所有新评论生成后直接发送，
没有草稿模式或逐条手动发送按钮。「保存并立即运行」明确触发该策略一次，
即使自动运行开关关闭也可使用；开关仅控制后续定时轮次。
保存某个策略只更新其配置、版本和下次执行时间，不改变另一个策略。
同账号的三类任务可以同时排队，生成阶段按顺序执行。
评论与私信各自去重和七天作者冷却；评论回访和评论探索仍共享去重。
搜索评论允许同一轮中每篇各发 Y 条，向模型提供本篇已生成正文，重复正文不发送。
同一搜索结果笔记未来轮次不会重复评论；私信也不会因更换分享开关重复联系。

每篇取一级评论第一页前五条参考，评论区不可用时仅根据正文生成并明确标注。
正文也读不到则不评论。三个策略均可在「执行 Agent」单独选择助手，复用现有
Channel/Multica 目录和账号绑定接口，不覆盖账号其他用途的配置。
未单独选择时沿用现有「内容创作」Agent，保持已有策略兼容。
列表展示 Multica 实时目录中的全部 Agent，不要求名称与账号昵称一致。
同一个 Agent 可以供不同账号调用；每次调用的账号身份、路由和历史记录仍各自隔离。
显式保存的 Agent 及路由快照在执行前重新核验；绑定失效时提示重新选择，
不按名称或其他账号的配置自动换助手。互动结果保存执行时的 Agent 快照。
目录暂不可用时仍允许关闭已保存的策略。
评论结果直接展示实际正文、账号、来源、目标作品、发送时间和状态；依据、
参考评论及平台回执放在展开详情。历史没有发送时间的记录显示生成时间，不伪造发送时间。

`.local/proactive-interactions.sqlite3` 保存设置、运行记录、正文和回执，权限 0600，
不保存 Cookie。`strategy_settings` 按账号和来源分别保存配置。
旧配置自动从小时换算为分钟，保留原已开启的直接发送策略及下次执行时间；
旧草稿模式不自动转成对外发送，历史草稿只读保留。
历史 items 表自动迁移，保留原 ID、正文、状态及回执；新增互动类型与每帖评论序号用于去重。
新增私信策略默认关闭，不会自动启用。

排除已连接账号和原评论监听停止联系的用户；提交前再次校验身份、配置版本、
停止联系名单和本轮发送上限。配置变化会取消尚未提交的新评论，不转存草稿。
提交前持久占用目标；网络错误或无 ID 回执进入不确定状态，禁止重发。
每次模型调用更新任务心跳，执行超过十五分钟无进展按中断处理，不自动重跑。
「已提交」表示平台返回评论 ID，不表示公开可见、通知送达或已读。

私信复用 `DmManualMessage` 的持久发送队列与现有 WebSocket worker，通过回执元数据标识
主动探索消息，不取消普通自动回复、不冒充本人接话。每条发送前重新检查账号身份、策略版本、
停止联系和人工接管状态；账号失效时保留未发送队列，核验恢复后继续。笔记分享失败或回执不确定时
取消后续文字，不重发分享。两条均收到成功回执才记为已提交；仅分享成功显示部分发送成功。
排队显示等待回执，重启前处于发送中的消息沿用现有不确定状态，不自动重发。
主动私信 WebSocket 回执明确返回 `-100` / `300012` 时，保留原消息为待发，
交由已有 IM 账号故障事件触发恢复；成功分享的链接不重发。未知回执继续进入不确定状态。

验证使用临时 SQLite 和模拟平台，没有发送真实测试评论。

前端在隔离目录通过类型检查及构建后，使用 `deploy/publish_frontend.py` 发布：
先同步公网资源，保留旧文件，再替换 HTML；不修改构建器生成的模块 URL。
浏览器验收包括手机和桌面、登录跳转、三卡片同时可用、逐篇评论配置、分享开关、分钟配置独立、结果正文显示、
深链接刷新和零运行时错误，不点击真实发送或运行按钮。

身份核验收到平台业务码 `-100` 时，运行记录显示登录失效及账号矩阵重新登录指引；
其他平台核验错误使用受控诊断文案，不展示原始响应或鉴权材料。身份核验失败时不生成、
不发送评论。历史仅保存异常类型的记录不事后推断改写。

主动互动身份检查发现明确登录失效/平台风险时，按当前 Cookie 版本校验后更新账号状态，
使用 `comment_identity_check` 来源、`account` 组件提交账号中心恢复工单；旧请求不能将新登录标为失效。
身份检查、搜索、读取作品/通知/评论参考及实际提交评论都识别明确的 `-100` / `300012`。
普通网络错误不当成登录失效；同一凭证故障事件去重，旧请求不能覆盖新登录。
已失效账号到达运行时间也生成 `waiting_login` 记录，不再静默跳过。
账号中心核验恢复后自动继续；平台明确拒绝登录的评论保留原生成正文，只续发确定未提交的内容。
已经成功或回执不确定的发送不重放；有历史 items 的恢复轮次不重新搜索生成整轮。
配置版本变化、关闭定时策略或账号身份变化会取消等待任务。
验证码、手机号和登录令牌不进入任务记录；短信冷却、绑定策略及确认去重由账号中心负责。
PC 自动续登验证码等待明确过期时，账号绑定仍启用且五分钟冷却满足后重试一次；
二次超时、结果未知、平台要求额外验证时保留明确维护状态，不无限发码。

## 明显广告筛选与同页补位（2026-10-16）

三类策略新增「自动过滤明显广告」，默认开启，可分别关闭后保存。搜索卡片或详情中的
明确广告类型、广告布尔标记、投放 ID，以及同时具有销售宣传和交易引导的文字，在调用
Agent 前本地过滤。普通个人分享、择偶帖中的私信邀请和避坑投诉不因这些词单独被过滤。
这是保守规则，不能识别所有软广或图片广告；未命中规则的内容仍交给原 Agent 判断。

搜索和推荐流仍只取原有第一页，最多扫描 60 条卡片。推荐词、明显广告、已互动笔记、
作者冷却、身份缺失或正文不可读时，从同页后续候选补位，最多准备配置的 X 篇有效笔记。
详情读取上限为 X 的三倍且最多 60 次，不额外翻页；互动回访仍只取各用户最新作品。
每篇评论数、私信人数、每日时段、身份恢复及不确定发送不重放的规则保持有效。
Agent 仍可跳过不合适内容，X 篇和发送数均为上限，不承诺必须发送满额。

「最近运行」显示扫描、交给 Agent、广告过滤、重复/冷却及 Agent 跳过计数；可展开逐篇原因。
诊断存入独立 `run_diagnostics` 表，按原运行的用户及账号权限读取，只记录作品身份、标题、
作者名称和受限长度的理由，不记录 Cookie、原始平台数据或鉴权链接。历史没有诊断时不推断补写。

主要为账号资料不足、条件不匹配，另有已互动候选占据前列的问题。样本不足以断言不存在广告。

账号停用使用 `disabled` 状态，定时 Cookie 健康检查跳过此状态，避免后台核验重新将其标为正常。
完整停用还须关闭对应 PC/Creator 的账号中心续登绑定和登录计划，并取消未执行维护请求；
业务策略、私信连接和评论/发布自动化分别保存开关，关闭业务开关不等于关闭自动续登。
